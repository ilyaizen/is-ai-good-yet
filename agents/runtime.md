# Runtime and deployment

This repo is a Node/npm SvelteKit deployment with a Python analysis pipeline. It is not a Bun deployment.

## Canonical identity

- production repo: `ilyaizen/is-ai-good-yet`
- legacy/private repo: `ilyaizen/is-ai-good-yet.com`
- current checkout on this box: `/srv/apps/is-ai-good-yet`
- old temporary migration checkout: `/tmp/is-ai-good-yet-public` (moved out of `/tmp`)

The `.com` repo is historical/private pipeline source. The public repo is the one that should run in production.

## Canonical Node runtime

- package manager: `npm`
- Node engine: `>=22.12.0`
- SvelteKit adapter: `@sveltejs/adapter-node`
- build command: `npm run build`
- production entrypoint: `build/index.js`
- start command: `HOST=0.0.0.0 node build/index.js`

## Pipeline layout

- source lives in `pipeline/`
- Python requirements live at `pipeline/requirements.txt`
- DB artifact path: `pipeline/data/pipeline.db`
- exported frontend data should be generated by the pipeline export phase, not hand-edited in app code
- runtime helpers resolve the DB relative to the repo/module, not `cwd`

## Python setup on Hetzner

Use a repo-root venv so Node scripts and Python commands agree on paths:

```bash
cd /srv/apps/is-ai-good-yet
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip setuptools wheel
python -m pip install -r pipeline/requirements.txt
python -m playwright install chromium
```

Pipeline dependencies include Playwright, Selenium/undetected-chromedriver, trafilatura, newspaper3k, Polars, PyArrow, Groq, Ollama, Pydantic, pytest, and sloppylint.

Environment requirements:

- `GROQ_API_KEY` for Groq-backed prefilter/sentiment analysis.
- optional proxy values in `.env`: `PROXY_SERVER`, `PROXY_USERNAME`, `PROXY_PASSWORD`.
- optional Ollama only if using local inference paths.

## Current pipeline caveat

`pipeline/run.py` currently parses `--phase ingest|scrape|analyze|all` but does not yet orchestrate the real phase modules. The real manual phases are still the modules under `pipeline/src/`, including:

```bash
cd /srv/apps/is-ai-good-yet/pipeline
../.venv/bin/python -m src.initial_e2e -v
../.venv/bin/python -m src.catch_up -v
../.venv/bin/python -m src.backfill_histre
../.venv/bin/python -m src.hn_resolver
../.venv/bin/python -m src.scraper -v
../.venv/bin/python -m src.clean_articles
../.venv/bin/python -m src.prefilter_content -v
../.venv/bin/python -m src.sentiment_analyzer -v
../.venv/bin/python -m src.export -v
```

Do not treat `npm run pipeline:*` as real orchestration until `pipeline/run.py` is wired to those modules.

## Scheduling direction

The production-safe path is:

1. Keep the SvelteKit app as the user-facing site.
2. Add a small authenticated admin route for pipeline control/status.
3. Add a server-side job runner that calls the Python pipeline through explicit subprocess commands.
4. Add a single-run lock so scheduled/manual runs cannot overlap.
5. Store run status/logs in SQLite.
6. Export static JSON after successful analysis.
7. Schedule catch-up runs with systemd timers or Hermes cron only after manual runs are stable.

No queue system yet. No distributed workers. No fake platform architecture. This is one small box.

## Verification

Node app:

```bash
npm run check
npm run build
HOST=0.0.0.0 node build/index.js
```

Pipeline setup:

```bash
. .venv/bin/activate
python -m pytest pipeline/tests -q
python -m playwright --version
```

DB-backed scripts:

```bash
test -f pipeline/data/pipeline.db
npm run diagnose:schema-migration
npm run verify:fix
npm run test:article-display
```

If the DB does not exist, DB-backed scripts should fail loudly with `Pipeline database not found at ...`.
