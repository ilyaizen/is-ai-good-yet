# Plan 003 — V2.4 version alignment + admin observability redesign

Created 2026-07-19 by Hermes. Cosmetic version alignment across the V2 namespace,
plus a focused redesign of `/v2/admin` to surface the data the ledger already holds
but does not show (dates, eligibility, scopes, categories) and to retire the
"raw JSON is the only detail surface" pattern.

#### Two consequences the user must understand before approving

1. **Database-filter effect.** `export_v2.py` selects analyses and prefilter
   decisions by version: `WHERE analysis_version = ?` with `ANALYSIS_VERSION` and
   `WHERE contract_version = ?` with `PREFILTER_CONTRACT_VERSION`
   (`export_v2.py:309`, `export_v2.py:313`, `export_v2.py:317`). After bumping
   those constants, the next export will find **zero** matching rows until the
   pipeline re-analyzes existing stories under the new versions. The public site
   will go unavailable until either (a) a re-analysis run completes, or (b) we
   preserve the previous static generation.

2. **Lockstep file contracts.** `v2-page-adapter.ts:validateGeneration` rejects
   any generation whose `contractVersion` does not match `EXPECTED_CONTRACTS`.
   Bumping `FILE_CONTRACTS` in Python requires bumping `EXPECTED_CONTRACTS` in TS
   and re-exporting. The skill's static-generation pitfall ("Atomic contract
   boundary") explicitly calls this out. The right sequence is:
   (i) bump both sides in the same PR, (ii) re-run the export locally to verify,
   (iii) deploy frontend and pipeline together, (iv) keep the previous
   `src/lib/data/v2/*.json` in git history so rollback is one revert.

### B. Admin observability — `/v2/admin` renders less than it fetches

`v2-admin-observability.svelte` loads fields it never displays:

1. **`story.hnTimestamp` is fetched, ordered by, but never rendered.** Loaded at
   `v2-admin-data.ts:361`; the summary `<small>` at line 141 renders points,
   comments, scopes — no date. The public `hn-story-card.svelte:29` shows it.
   This is the single most confusing omission in the admin.
2. **`story.eligible` is fetched but has no badge in the summary row.** The only
   place it surfaces is the expanded panel ("Eligible" / "Rejected" / "Not
   checked"). The ledger cannot be scanned for "what passed prefilter."
3. **Scopes are joined into a flat string** (`story.scopes.join(" · ")`), losing
   the per-scope chip treatment the public card has.
4. **`story.url` is loaded but the title is not a link.** Title renders as
   `<strong>`; you cannot click through to HN or the article.
5. **The disclosure chevron (line 146 `<i>⌄</i>`) is per-row, not "expand all."**
   Reads as "the expand/collapse button on the right" because it sits at the
   right edge of the summary via `justify-content: space-between`. There is no
   expand-all / collapse-all control today; the chevron is fine but its job is
   unclear because no header-level toggle exists.
6. **Raw JSON is the only detail surface** for tokens, parameters, comment
   analysis results. No badges, no derived metrics (tokens/comment, duration
   from `inferenceTimeMs`, confidence bars, polarization indicator).
7. **Orchestration table has no duration column** despite having both timestamps.
8. **`V2AdminStoryDetails` does not include `url` or `domain`** — list-level
   story has it, the detail endpoint does not.

### C. "Beyond admin" — public `/v2` parity

The public card (`hn-story-card.svelte`) already shows date + scopes + points +
domain. The admin ledger should match or exceed that surface. No public-side
defects found in this audit; the gap is admin-only.

## Scope

### In scope

- S1. Bump every `v2.X.Y` version string to `v2.4.x` per the inventory table.
- S2. Surface `hnTimestamp`, `eligible`, and per-scope badges in the admin
  story-summary row; make the story title link to its HN URL.
- S3. Add a real "Expand all / Collapse all" control at the ledger header.
- S4. Replace the JSON-only detail blocks with categorized, badge-driven UI for
  the high-signal fields (tokens, duration, confidence, evidence counts) while
  keeping the raw JSON as a collapsible fallback.
- S5. Add a duration column to the orchestration table.

### Out of scope

- Any change to `GLOBAL_INFLUENCE_VERSION` or `MANIFEST_VERSION` — neither
  carries a `v2.X.Y` token and bumping them is a semantic change, not cosmetic.
- Changing what the pipeline _does_. This plan only changes labels the pipeline
  emits; behavior is identical. (User confirmed cosmetic alignment.)
- Any change to the public `/v2` story card. The public side already shows the
  fields the admin is missing; no work needed there.
- Database migrations. The `v2_*` SQLite tables are unchanged.

## Risk classes

- **R1 — Public site goes dark after deploy.** Mitigated by S1 lockstep rule:
  bump Python + TS together, re-export locally, deploy in one go, keep previous
  generation in git history.
- **R2 — Post-bump export returns zero records.** `export_v2.py` filters by
  version. Either (a) re-analyze under new versions, or (b) accept a one-cycle
  gap where the site shows the previous generation until the next pipeline run.
  Pre-existing static generation survives the bump because `validateGeneration`
  reads from the new files; it does not re-query the DB.
- **R3 — CRLF churn on Windows-edited files.** Per skill pitfall: reconstruct
  small semantic patches against originals; verify with
  `git diff --ignore-space-at-eol --stat`.
